# 📡 Certificate Radar

Централизованное обнаружение, инвентаризация и контроль TLS-сертификатов корпоративной инфраструктуры (Проект 2 из ТЗ хакатона). Принцип: **«Обнаружить проблему до того, как она станет инцидентом»**.

## Возможности (MVP по ТЗ §3.11)

- ✅ Загрузка списка DNS / IP / URL / IP-диапазонов (`a.b.c.d-e`, CIDR)
- ✅ Автоматическое подключение к TLS-сервисам (по умолчанию 443, любой порт)
- ✅ Сбор атрибутов сертификата: CN, SAN, Issuer, Thumbprint (SHA-256), срок действия
- ✅ Days Left + статусы **OK / Information / Warning / Critical / Expired** (пороги 60/30/14 настраиваются)
- ✅ Проверка соответствия DNS-имени (CN/SAN, wildcard)
- ✅ Проверка цепочки доверия (структура + корень в хранилище доверия ОС)
- ✅ Выявление проблем: истёкший, скоро истекает, self-signed, ошибка цепочки, mismatch имени, слабая криптография (RSA<2048/EC<256, MD5/SHA-1)
- ✅ **Risk Score 0–100** с объяснением причин и рекомендациями (§3.9)
- ✅ Web Dashboard: KPI, фильтры и сортировка по сервису/владельцу/издателю/сроку/статусу, ближайшие истечения, динамика Risk Score
- ✅ Владельцы и критичность сервисов (клик по владельцу в таблице)
- ✅ Уведомления по порогам **60/30/14/7/1 дней** — Log + Telegram + Email (дедупликация на каждый порог)
- ✅ Экспорт **CSV / Excel / HTML**
- ✅ Read-only сканирование, минимальные права, журналирование (§4.2)

```bash

```

## Демо-стенд для презентации (ТЗ §5.2)

```bash
python -m demo.generate_targets
```

Поднимает 6 локальных HTTPS-сервисов со всеми состояниями из сценария демонстрации:

| Порт | Состояние |
|------|-----------|
| 8443 | валидный сертификат |
| 8444 | истекает через 10 дней (Critical) |
| 8445 | истёкший сертификат (Expired) |
| 8446 | self-signed |
| 8447 | разорванная цепочка (без intermediate) |
| 8448 | несоответствие DNS-имени (mismatch) |

Список целей для вставки в Dashboard уже предзаполнен: `localhost:8443 … 8448`.
Сервисы слушают `127.0.0.1` и используют имя `localhost`, поэтому демо работает
без правок файла hosts.

> Чтобы порт 8443 показал «цепочка OK», установите `demo_certs/demo_ca.crt` в доверенные корневые ЦС Windows («Установить сертификат → Текущий пользователь → Доверенные корневые центры сертификации»). Без установки все демо-цепочки честно покажутся ненадёжными — это тоже корректная демонстрация.

## Сценарий демонстрации (5 минут)

1. Запустить `python -m demo.generate_targets` (окно 1) и `python run.py` (окно 2)
2. Открыть `http://127.0.0.1:8000` → нажать **«Новое сканирование» → «Запустить»**
3. Dashboard покажет: Expired на 8445, Critical на 8444, mismatch на 8448, сломанную цепочку на 8447, self-signed на 8446
4. Кликнуть по владельцу у критичного сервиса → назначить ответственного, пометить «critical» → Risk Score вырастет
5. Показать уведомления (порог 14 дней сработал для 8444), выгрузить HTML-отчёт
6. Показать фильтры: «только проблемные», сортировка по Risk, статусам, издателю

## Архитектура

```
cert_radar/
├── targets.py      # парсер целей: DNS/IP/URL/CIDR/диапазоны
├── tls_client.py   # async TLS-зонд: сертификат + полная цепочка
├── analysis.py     # парсинг X.509, цепочка доверия, DNS-match, слабая криптография
├── risk.py         # Risk Score 0-100, статусы, находки + рекомендации
├── scanner.py      # оркестратор (asyncio, семафор параллельности)
├── storage.py      # SQLite: инвентарь, история сканов, тренд, журнал уведомлений
├── notifications.py# пороги 60/30/14/7/1, Telegram/Email/log, дедупликация
├── exporters.py    # CSV / Excel / HTML
├── config.py       # пороги и веса риска (env + UI)
└── app.py          # FastAPI: REST API + статический Dashboard
static/index.html   # Dashboard (без сборки, чистый JS)
demo/               # генератор демо-стенда
tests/              # pytest
```

Модульность (ТЗ §4.1): новые проверки добавляются функцией в `analysis.py` + правилом в `risk.py`; новые каналы уведомлений — функцией в `notifications.py`; новые источники (например, Windows-хранилище сертификатов) — новым collector-модулем.

## API (для интеграции)

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/scan` | сканирование `{targets, timeout?, concurrency?}` |
| GET | `/api/services` | инвентарь с последним состоянием |
| GET | `/api/summary` | KPI для дашборда |
| GET | `/api/trend` | динамика Risk Score по сканам |
| POST | `/api/services/{endpoint}/owner` | владелец/критичность |
| GET | `/api/export/{csv\|xlsx\|html}` | отчёты |
| GET/POST | `/api/settings` | пороги, Telegram, SMTP |
