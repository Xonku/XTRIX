ЧАСТЬ A. ТЕОРИЯ ЗА 2 МИНУТЫ (простыми словами)
───────────────────────────────────────────────────────────────────────────

ЧТО ТАКОЕ СЕРТИФИКАТ?
  Это цифровой «паспорт» сайта. Когда браузер заходит на https-сайт,
  сервер показывает этот паспорт. В нём написано:
    • КОМУ выдан       (CN = имя сайта, например iis-demo.local)
    • КЕМ выдан        (Issuer = центр сертификации, ЦС)
    • ДО КОГДА годен   (срок действия)
    • ОТПЕЧАТОК        (thumbprint — уникальный номер паспорта)

ЗАЧЕМ ОН НУЖЕН?
  Чтобы браузер мог проверить: «это правда тот сайт, куда я шёл,
  а не подстава, и канал шифруется». Нет паспорта / просрочен /
  самодельный → браузер красное окно с предупреждением.

ЧТО ТАКОЕ .PFX ФАЙЛ И ЗАЧЕМ ОН МНЕ?
  .pfx — это ОДИН файл-контейнер, внутри которого лежит сам сертификат
  ПЛЮС закрытый ключ (секретная часть, без которой сервер не может
  работать по https). Windows-серверы импортируют сертификаты именно
  в .pfx. 

ОТКУДА ИХ БРАТЬ?
  В реальной жизни: купить у центра сертификации (DigiCert, Sectigo...)
  или выпустить в корпоративном ЦС (Active Directory Certificate Services).
  Для ДЕМО это не нужно! Я уже сгенерировал тебе 6 готовых .pfx файлов
  командой:  python -m demo.make_pfx
  Они лежат в папке:  demo_certs\pfx\
  Пароль у всех файлов:  demo

ЧТО В КАЖДОМ ФАЙЛЕ (это и есть все сценарии из ТЗ §5.2):

  demo_ca.crt       «корневой ЦС» — наш самодельный «министерство,
                    которое выдаёт паспорта». Установи его на сервере
                    в доверенные — тогда сертификаты от него будут
                    считаться настоящими.
  01_valid.pfx      нормальный паспорт на 1 год      → всё зелёное
  02_expiring.pfx   истекает через 10 дней           → Critical
  03_expired.pfx    истёк 5 дней назад               → Expired
  04_selfsigned.pfx самоподписанный (сам себе выдал) → подозрительный
  05_brokenchain.pfx выдан через посредника, но посредника на сервере
                    НЕТ → «разорванная цепочка доверия»
  06_mismatch.pfx   паспорт выдан ДРУГОМУ сайту (other-name.local)
                    → несовпадение имени


ЧАСТЬ B. ГОТОВИМ ВИРТУАЛЬНУЮ МАШИНУ
───────────────────────────────────────────────────────────────────────────

Если VM с Windows Server 2025 уже создана — пропусти этот шаг.

1. Создай VM в Hyper-V / VirtualBox / VMware:
      - CPU: 2 ядра, RAM: 4 ГБ, диск: 60 ГБ
      - ISO: Windows Server 2025 (оценка с сайта Microsoft, 180 дней)
2. При установке выбери «Desktop Experience» (с рабочим столом!).
3. Задай пароль администратора и запомни его.
4. НАСТРОЙ СЕТЬ (важно! чтобы твой основной комп видел VM):
   • В настройках VM сеть должна быть «Внутренняя» или «NAT» или
     «Мост» (Bridge) — любой вариант, где VM получит IP вида 192.168.x.x
   • Внутри VM: Параметры → Сеть → посмотри IP-адрес (или в cmd:
         ipconfig
     ). Запиши его, например 192.168.56.10
   • Если IP вида 169.254.x.x — сеть не настроена: задай вручную
     статический IP (например 192.168.56.10, маска 255.255.255.0).
5. ПРОВЕРКА СВЯЗИ: с твоего основного компа в cmd:
         ping 192.168.56.10
   Должны идти ответы. Если нет — дальше не идёт, чини сеть.


ЧАСТЬ C. ПЕРЕКАЛЫВАЕМ ФАЙЛЫ НА VM
───────────────────────────────────────────────────────────────────────────

Скопируй на виртуалку в папку C:\Certs (создай её):
   • всю папку demo_certs\pfx\  (7 файлов: demo_ca.crt + 6 .pfx)
   • файл demo\iis_setup.ps1

Способы скопировать:
   • Общая папка VirtualBox/VMware (Devices → Shared Folders)
   • Перетаскивание мышкой (в VMware часто работает)
   • Через сеть: на основном компе расшарь папку (правый клик →
     Свойства → Доступ), из VM открой \\192.168.56.1\имя_папки


ЧАСТЬ D. СПОСОБ 1 — АВТОМАТ (1 команда)
───────────────────────────────────────────────────────────────────────────

На VM: открой PowerShell КАК АДМИНИСТРАТОР (правый клик на Пуск →
«Windows PowerShell (администратор)») и выполни:

      powershell -ExecutionPolicy Bypass -File C:\Certs\iis_setup.ps1

Скрипт сам:
   [1/6] установит IIS (роль веб-сервера)
   [2/6] установит demo_ca.crt в «Доверенные корневые ЦС»
   [3/6] импортирует все 6 .pfx в хранилище «Личные»
         (пароль demo подставится сам)
   [4/6] создаст 6 сайтов на портах 9441-9446 и привяжет им сертификаты
   [5/6] откроет эти порты в брандмауэре
   [6/6] пропишет имена iis-demo.local и other-name.local в hosts
   В конце напишет IP виртуалки — ЗАПОМНИ ЕГО.

Если скрипт заругался — смотри ЧАСТЬ G (проблемы) или делай руками (ЧАСТЬ E).


ЧАСТЬ E. СПОСОБ 2 — РУКАМИ ЧЕРЕЗ ОКНА (если хочешь показать «реальную работу»)
───────────────────────────────────────────────────────────────────────────

E1. УСТАНОВКА IIS
    Диспетчер серверов → «Добавить роли и компоненты» →
    Тип установки: «Установка ролей или компонентов» →
    выбери свой сервер → в списке ролей поставь галочку
    «Веб-сервер (IIS)» → далее-далее → «Установить».
    Проверка: открой в браузере VM http://localhost — синяя страница IIS.

E2. ИМПОРТ КОРНЕВОГО ЦС (чтобы «паспорта» считались настоящими)
    Win+R → набери certlm.msc → Enter.
    Слева: «Доверенные корневые центры сертификации» → «Сертификаты» →
    правый клик по «Сертификаты» → «Все задачи» → «Импорт» →
    Далее → Обзор → выбери C:\Certs\demo_ca.crt →
    «Поместить все сертификаты в следующее хранилище» (там уже стоит
    «Доверенные корневые центры сертификации») → Далее → Готово.

E3. ИМПОРТ 6 СЕРТИФИКАТОВ (.pfx)
    Там же в certlm.msc: слева «Личные» → «Сертификаты» →
    правый клик → «Все задачи» → «Импорт» → Далее → Обзор →
    выбери 01_valid.pfx → пароль: demo →
    галочку «Пометить этот ключ как экспортируемый» можно поставить →
    Далее → «Поместить все сертификаты в следующее хранилище»
    (должно быть «Личные») → Далее → Готово.
    ПОВТОРИ для всех 6 файлов 01..06.
    После импорта в списке «Личные» появятся 6 сертификатов с именами
    iis-demo.local и other-name.local. Если двойной клик — увидишь
    срок действия: у 03_expired красный крестик, у 02_expiring
    жёлтый восклицательный знак. Это уже красиво для показа!

E4. СОЗДАНИЕ САЙТОВ В IIS
    Пуск → «Диспетчер служб IIS» (Internet Information Services Manager).
    Слева: сервер → «Сайты» → правый клик → «Добавить веб-сайт»:
       Имя сайта:        demo-valid
       Физический путь:  C:\inetpub\demo-valid  (создастся сам)
       Тип:              https
       IP-адрес:         «Все свободные»
       Порт:             9441
       Имя узла:         (оставь ПУСТЫМ — важно, иначе не заработает)
       Сертификат SSL:   выбери «iis-demo.local» (тот, что годен)
    → ОК. Сайт создан и сразу слушает https на порту 9441.

    ПОВТОРИ ещё 5 раз (или создай один и скопируй):
       demo-expiring    порт 9442   сертификат iis-demo.local (жёлтый)
       demo-expired     порт 9443   сертификат iis-demo.local (красный)
       demo-selfsigned  порт 9444   сертификат iis-demo.local (самоподпис.)
       demo-broken      порт 9445   сертификат iis-demo.local (05_broken)
       demo-mismatch    порт 9446   сертификат other-name.local

    Каждому сайту положи страничку: в папке сайта создай index.html
    с любым текстом, например:
       <h1>Demo: expired certificate</h1>

E5. БРАНДМАУЭР (открыть порты)
    В PowerShell администратора на VM:
       Enable-NetFirewallRule -DisplayName "World Wide Web Services (HTTPS)"
    или для наших портов:
       9441..9446 | % { New-NetFirewallRule -DisplayName "CR $_" `
          -Direction Inbound -Protocol TCP -LocalPort $_ -Action Allow }

E6. ПРОВЕРКА ВНУТРИ VM
    Открой в браузере VM:  https://localhost:9443
    Браузер покажет «Ваше подключение не защищено» — ЭТО ХОРОШО!
    Это и есть наш истёкший сертификат, браузер его сам распознал.
    Нажми «Дополнительно» → «Перейти на сайт» — увидишь страничку.
    Так и должно быть. Закрой.


ЧАСТЬ F. СВЯЗЫВАЕМ С CERTIFICATE RADAR И СКАНИРУЕМ
───────────────────────────────────────────────────────────────────────────

F1. НА ОСНОВНОМ КОМПЕ пропиши имя VM в hosts (чтобы сканер проверял
    «по-настоящему», по имени):
    Открой Блокнот КАК АДМИНИСТРАТОР → Файл → Открыть →
    C:\Windows\System32\drivers\etc\hosts (выбери «Все файлы») →
    добавь строку (IP — из ЧАСТИ D):
        192.168.56.10   iis-demo.local
    Сохрани.

F2. ОТКРОЙ ДАШБОРД: http://127.0.0.1:8000
    (если не запущен: python run.py)

F3. РАСКРОЙ «Новое сканирование» и вставь цели (IP — твой):

        192.168.56.10:9441
        192.168.56.10:9442
        192.168.56.10:9443
        192.168.56.10:9444
        192.168.56.10:9445
        192.168.56.10:9446

    или с именами (если сделал F1):
        iis-demo.local:9441
        iis-demo.local:9442
        iis-demo.local:9443
        ...

F4. ЖМИ «Запустить сканирование». Через пару секунд в таблице:

    :9441  OK            зелёный, цепочка ✓ (мы установили demo_ca!)
    :9442  Critical      «истекает через 10 дней»
    :9443  Expired       «истёк 5 дней назад»
    :9444  self-signed   «самоподписанный сертификат»
    :9445  ✗ цепочка     «issuer not provided» (посредника нет)
    :9446  ✗ mismatch    «имя не совпадает» (паспорт другого сайта)

    Именно это и требует демонстрационный сценарий ТЗ §5.2 —
    все 6 состояний сертификатов показаны вживую на Windows Server + IIS.

F5. Для «вау»: кликни владельцу у :9442 → «Пётр, critical» →
    риск вырос. Затем кнопка Excel — отчёт для жюри.


ЧАСТЬ G. ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
───────────────────────────────────────────────────────────────────────────

  ping с компа до VM не проходит
      → Сеть VM не в том режиме. Поставь «Мост» (Bridge) или
        «Внутренняя» + статические IP на обоих. Брандмауэр VM:
        включи правило «Общий доступ к файлам и принтерам (Echo - ICMP)»
        или временно выключи брандмауэр для проверки.

  Скрипт ps1 не запускается: «выполнение сценариев отключено»
      → Запускай так, как в ЧАСТИ D (там уже есть -ExecutionPolicy Bypass).
        Либо вручную: PowerShell админ → Set-ExecutionPolicy RemoteSigned.

  «Import-PfxCertificate: пароль не подходит»
      → Файлы побились при копировании (скопируй заново) или пароль
        не "demo". Проверь размер файлов (по ~2.5-3.5 КБ).

  Сайт не открывается из основного компа, но открывается в VM
      → Порт закрыт брандмауэром VM (ЧАСТЬ E5).
        Или сайт слушает не тот IP: в IIS → Привязки сайта →
        IP-адрес = «Все свободные».

  Сканер пишет Unknown / connection refused
      → VM выключена, IIS не установлен, сайт не запущен (в IIS
        справа «Управление веб-сайтом» → «Пуск»), порт не тот.

  В сертификате порта 9441 цепочка всё равно ✗
      → Не установлен demo_ca.crt в «Доверенные корневые ЦС»
        (ЧАСТЬ E2). Это НОРМАЛЬНО и тоже показательно — просто
        скажи жюри: «админ забыл установить корневой ЦС — вот
        ещё один вид риска».

  Браузер VM ругается на https://localhost:9443
      → Так и задумано: он ругается на истёкший/самоподписанный
        сертификат. «Дополнительно» → «Перейти».

  Хочу другие имена/порты
      → Имена зашиты в demo/make_pfx.py (константа MAIN_NAME),
        порты — в demo/iis_setup.ps1 (словарь $plan).
        Поменял → python -m demo.make_pfx → заново скопируй pfx на VM.


ЧАСТЬ H. ШПАРГАЛКА-ПОСЛЕДОВАТЕЛЬНОСТЬ (распечатай)
───────────────────────────────────────────────────────────────────────────

  [на основном компе]
    1. python -m demo.make_pfx         → появятся файлы в demo_certs\pfx
    2. Скопировать demo_certs\pfx + demo\iis_setup.ps1 на VM в C:\Certs
    3. Записать IP виртуалки

  [на VM, PowerShell администратора]
    4. powershell -ExecutionPolicy Bypass -File C:\Certs\iis_setup.ps1

  [на основном компе]
    5. hosts:  192.168.56.10  iis-demo.local   (опционально)
    6. http://127.0.0.1:8000 → «Новое сканирование» →
       вставить IP:9441..9446 → «Запустить»
    7. Показывать жюри: Expired, Critical, self-signed,
       broken chain, mismatch — всё по сценарию ТЗ §5.2 ✓
