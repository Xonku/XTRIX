ЧАСТЬ 0. ЧТО ЭТО ВООБЩЕ ТАКОЕ
───────────────────────────────────────────────────────────────────────────

Это программа, которая автоматически проверяет SSL/TLS-сертификаты на
серверах и предупреждает ЗАРАНЕЕ, пока что-то не сломалось.

Зачем это нужно:
  • У каждого сайта/VPN/почты есть сертификат — у него есть срок годности.
  • Сертификат истёк → браузеры блокируют сайт → сервис лежит.
  • Ручной учёт в Excel ведут единицы, и все забывают.
  • Эта программа находит проблемы за 60 дней до аварии.


ЧАСТЬ 1. ЗАПУСК (3 команды)
───────────────────────────────────────────────────────────────────────────

Открой ТРИ окна командной строки (cmd) в папке проекта.

  Окно 1 — ПРОВЕРКА, ЧТО ВСЁ УСТАНОВЛЕНО (первый раз):
      pip install -r requirements.txt

  Окно 1 — ДЕМО-СТЕНД (6 тестовых серверов с плохими сертификатами):
      python -m demo.generate_targets
      ► После запуска НЕ закрывай окно — там крутятся серверы на портах
        8443-8448. Чтобы остановить — Ctrl+C.

  Окно 2 — САМА ПРОГРАММА (дашборд):
      python run.py
      ► Не закрывай окно. Программа работает на http://127.0.0.1:8000

  Окно 3 — ТЕСТЫ (проверить, что ничего не сломалось):
      python -m pytest
      ► Должно быть "21 passed".

ДАЛЬШЕ: открой браузер (Chrome/Edge) и набери в адресной строке:

      http://127.0.0.1:8000

Появится тёмный дашборд — это и есть главный экран программы.


ЧАСТЬ 2. ГЛАВНЫЙ ЭКРАН — ЧТО ТЫ ВИДИШЬ
───────────────────────────────────────────────────────────────────────────

Сверху вниз:

  1) ШАПКА с кнопками справа:
       [⟳ Обновить]     — обновить все данные на экране
       [CSV]            — скачать отчёт-таблицу (открывается в Excel)
       [Excel]          — скачать красивый .xlsx с цветными статусами
       [HTML-отчёт]     — скачать самодостаточную страничку,
                          можно переслать начальнику в мессенджер

  2) КУБИКИ-СЧЁТЧИКИ (KPI). Каждый показывает число:
       Сертификатов  — сколько всего серверов в базе
       OK            — зелёные, срок >60 дней, всё хорошо
       Information   — голубые, 31-60 дней, просто запомнить
       Warning       — жёлтые, 15-30 дней, пора планировать замену
       Critical      — красные, 0-14 дней, СРОЧНО
       Expired       — тёмно-красные, уже истёк, сервис в опасности
       Max Risk      — самый высокий риск среди всех (0-100)
       Без владельца — сколько серверов никто не назначил ответственным

  3) БОЛЬШАЯ ТАБЛИЦА — по строке на каждый проверенный сервер.
       Подробно про колонки — в ЧАСТИ 4.

  4) СПРАВА: «Ближайшее истечение» — топ-10 самых срочных.
       Дальше «Динамика Risk Score» — график по истории сканирований.
       Дальше «Уведомления» — что программа отправляла админам.

  5) ВНИЗУ два складных блока:
       «🔍 Новое сканирование» — запустить проверку (ЧАСТЬ 3)
       «⚙️ Настройки»          — пороги и уведомления (ЧАСТЬ 6)


ЧАСТЬ 3. КАК СКАНИРОВАТЬ (ГЛАВНОЕ ДЕЙСТВИЕ)
───────────────────────────────────────────────────────────────────────────

Шаг 1. Кликни на блок «🔍 Новое сканирование» — он раскроется.

Шаг 2. В большом поле уже вставлен готовый список демо-целей:
           localhost:8443
           localhost:8444
           ... и т.д.
       Для первого запуска НЕ ТРОГАЙ его — просто жми кнопку.

Шаг 3. Нажми [▶ Запустить сканирование].
       Полоска пробежит 2-5 секунд — готово.

Шаг 4. Смотри наверх: таблица заполнена, кубики посчитаны.
       Программа при сканировании:
         • подключается к каждому серверу;
         • забирает его сертификат (сам сервер его сам показывает);
         • проверяет срок, цепочку доверия, имя, криптографию;
         • ставит оценку риска 0-100 и пишет рекомендации.

ВАЖНО: ничего «подключать» не надо. Сканер работает как браузер:
пришёл по сети — посмотрел, что тебе показали — ушёл. Он НИЧЕГО
не меняет на проверяемых серверах (режим Read-only, как в ТЗ).


ЧАСТЬ 3.1. ЧТО МОЖНО ВПИСАТЬ В ПОЛЕ ЦЕЛЕЙ (форматы)

По одной строке или через запятую. Можно смешивать всё:

  google.com                      обычный сайт (порт 443 подставится сам)
  mail.company.kz:993             сервер на НЕстандартном порту
  https://portal.kz:8443          сайт в виде URL — порт возьмётся из ссылки
  192.168.1.10                    сервер по IP-адресу
  192.168.1.10-192.168.1.50       ДИАПАЗОН IP — проверит все 41 адрес
  192.168.1.5-20                  короткий диапазон (последний октет)
  192.168.1.0/28                  ЦЕЛАЯ ПОДСЕТЬ (маска CIDR)
  localhost:8443                  свой локальный тестовый сервис

Кнопка «Таймаут» — сколько секунд ждать сервер (если сервер далеко/медленный,
поставь 10). «Потоки» — сколько проверять одновременно (больше = быстрее,
но 32 обычно достаточно даже для сотен адресов).

ПРОВЕРКА НА ЖИВЫХ САЙТАХ (эффектно для жюри):
  Вставь в поле:
      expired.badssl.com
      wrong.host.badssl.com
      self-signed.badssl.com
      google.com
  Жми «Запустить» — на настоящем интернете найдёт истёкший сертификат,
  несовпадение имени и самоподписанный, а google.com будет зелёным.


ЧАСТЬ 4. ТАБЛИЦА — ЧИТАЕМ РЕЗУЛЬТАТЫ
───────────────────────────────────────────────────────────────────────────

Колонки слева направо:

  Сервис        адрес:порт проверяемого сервера.
                Если рядом красный ярлык «КРИТ» — ты сам пометил сервис
                критичным, и его риск пересчитан выше.

  Статус        цветной бейдж:
                  OK          >60 дней — ничего не делать
                  Information 31-60 дней — держать на заметке
                  Warning     15-30 дней — планировать замену
                  Critical    0-14 дней — менять сейчас
                  Expired     <0 дней — УЖЕ истёк, сервис ломается
                  Unknown     сервер не ответил (выключен/не TLS/опечатка)

  Risk          оценка 0-100. Чем больше — тем страшнее:
                  0-24  Low      зелёный
                  25-49 Medium    салатовый
                  50-74 High      оранжевый
                  75-100 Critical красный
                Из чего складывается: срок (главное) + сломанная цепочка
                + несовпадение имени + слабая криптография + «критичность».

  Осталось      сколько дней до конца срока (у истёкших — минус).

  Сертификат    имя (CN) сертификата — кому он выдан.

  Издатель      кто выпустил: DigiCert, Sectigo, Internal CA (свой ЦС)...

  Истекает      дата конца срока.

  Цепочка       ✓ — цепочка доверия цела и доходит до корня,
                которому ОС доверяет.
                ✗ цепочка — наведи мышку, увидишь причину:
                  «issuer not provided» — сервер не отдал промежуточный
                  сертификат (забыли установить на сервере);
                  «not in trust store» — корень неизвестен (self-signed).

  DNS           ✓ — имя сайта совпадает с сертификатом.
                ✗ mismatch — сертификат выдан ДРУГОМУ имени!
                Это либо ошибка, либо подмена сервера.

  Владелец      кто отвечает за этот сервер. «не задан» = никто.
                Кликни — впишешь (см. ЧАСТЬ 5).


ЧТО ДЕЛАТЬ С НАЙДЕННЫМ (частые случаи):

  • Expired          — срочно перевыпускать сертификат.
  • Critical (9 дн)  — запускать перевыпуск сегодня-завтра.
  • self-signed      — заменить на сертификат от корпоративного/публичного ЦС.
  • ✗ цепочка        — доустановить промежуточные сертификаты на сервер.
  • ✗ mismatch       — перевыпустить с правильным именем в SAN.
  • Unknown          — проверить: сервер включён? порт тот? это точно TLS?


ЧАСТЬ 4.1. ФИЛЬТРЫ НАД ТАБЛИЦЕЙ

  «Фильтр: сервис»   пиши часть адреса, например "844" — останутся
                     только строки с 8443-8448.
  «Фильтр: владелец» пиши "Иван" — только его серверы.
  «Фильтр: издатель» пиши "DigiCert" — только его сертификаты.
  «Все статусы»      выбери, например, Critical — только красные.
  «только проблемные»галочка: скроет всё здоровое.

СОРТИРОВКА: кликни на заголовок любого столбца (там где ⇅) —
отсортирует. Ещё раз клик — в обратном порядке.


ЧАСТЬ 5. ВЛАДЕЛЬЦЫ И КРИТИЧНОСТЬ
───────────────────────────────────────────────────────────────────────────

Зачем: чтобы у каждого сервера был ответственный, и чтобы важные
сервисы (платёжка, VPN) имели повышенный риск.

Как назначить:
  1. В таблице найди колонку «Владелец».
  2. Кликни на «не задан» (курсив).
  3. В окне введи имя, например: Пётр
  4. Enter → готово, имя сохранилось в базу навсегда.

Как пометить сервер КРИТИЧНЫМ (риск вырастет на +25):
  Кликни на владельца и введи:  Пётр, critical
  Вернуть обратно:              Пётр, normal


ЧАСТЬ 6. НАСТРОЙКИ: ПОРОГИ И УВЕДОМЛЕНИЯ
───────────────────────────────────────────────────────────────────────────

Раскрой внизу блок «⚙️ Настройки порогов и уведомлений».

  Пороги (дней)     список через запятую: 60, 30, 14, 7, 1
                    Когда у сертификата остаётся МЕНЬШЕ числа —
                    программа отправляет уведомление. Каждый порог
                    срабатывает ОДИН раз (без спама). Если сертификат
                    продлили — счётчик сбрасывается.

  Telegram token    токен бота (получить у @BotFather в Telegram:
                    /newbot → имя → токен вида 1234567:AAEhBO...).
  Chat ID           твой чат (узнать можно у бота @userinfobot).
  SMTP              почтовый сервер host:port, например smtp.kz:587
                    (полные данные почты задаются переменными окружения
                    CERT_RADAR_SMTP_USER / _PASSWORD / _FROM / _TO).

  [Сохранить]       записать в базу.

Куда падают уведомления:
  • всегда — в блок «Уведомления» на дашборде и в логи;
  • если заполнен Telegram — в чат Telegram;
  • если заполнен SMTP — на почту.

ПРИМЕР УВЕДОМЛЕНИЯ:
  [Critical] localhost:8444 expires in 9 day(s) (threshold 60d) - localhost


ЧАСТЬ 7. ЭКСПОРТ ОТЧЁТОВ
───────────────────────────────────────────────────────────────────────────

Кнопки в шапке справа. Экспортируется последний результат сканирования.

  CSV     простой текст с разделителем «;» — откроется в любом Excel.
  Excel   .xlsx с цветными строками по статусам, фильтрами, шапкой.
  HTML    красивая страница одним файлом — двойной клик, открывается
          без интернета. Удобно вложить в письмо/чат.

Отчёт содержит: сервис, статус, риск, дней осталось, имя сертификата,
издатель, дату, цепочку, DNS-совпадение, владельца, ошибку.


ЧАСТЬ 7.5. РЕАЛЬНЫЙ СТЕНД НА WINDOWS SERVER + IIS
───────────────────────────────────────────────────────────────────────────

ТЗ требует демонстрацию на Windows Server с IIS. Готовый план — в файле
iis_setup.txt в корне проекта. Коротко:

  python -m demo.make_pfx     — создать 6 сертификатов .pfx (пароль: demo)
  скопировать их на VM + demo/iis_setup.ps1 в C:\Certs
  на VM: powershell -ExecutionPolicy Bypass -File C:\Certs\iis_setup.ps1
  сканировать:  <ip-vm>:9441 ... <ip-vm>:9446

Подробно (сеть VM, импорт через certlm.msc руками, привязки IIS,
hosts, проблемы) — читай iis_setup.txt.


ЧАСТЬ 8. ДЕМО-СТЕНД: ЧТО НА КАКОМ ПОРТУ
───────────────────────────────────────────────────────────────────────────

Скрипт python -m demo.generate_targets поднимает 6 тестовых серверов:

  localhost:8443   ПРАВИЛЬНЫЙ сертификат (цепочка от демо-ЦС)
  localhost:8444   истекает через 10 дней      → покажет Critical
  localhost:8445   истёк 5 дней назад          → покажет Expired
  localhost:8446   самоподписанный             → покажет self-signed
  localhost:8447   разорванная цепочка         → покажет ✗ цепочка
  localhost:8448   сертификат другого имени    → покажет ✗ mismatch

Хочешь СВОЙ тестовый сертификат? Открой demo/generate_targets.py,
найди словарь PORTS и добавь строку:
      8449: ("expiring", 3),        # истекает через 3 дня
Виды: "valid", "expiring", "expired", "selfsigned", "brokenchain",
      "mismatch". Перезапусти скрипт — сервер появится на 8449.

БОНУС для показа «цепочка OK»: двойной клик по demo_certs/demo_ca.crt
→ «Установить сертификат» → «Текущий пользователь» →
«Доверенные корневые центры сертификации» → готово.
Пересканируй 8443 — цепочка станет ✓.


ЧАСТЬ 9. ПРЕЗЕНТАЦИЯ ЖЮРИ ЗА 3 МИНУТЫ (скрипт)
───────────────────────────────────────────────────────────────────────────

  0:00  «Каждый простой из-за сертификата можно было предотвратить.
         Мы делаем это автоматически» — открой пустой дашборд.
  0:30  Раскрой «Новое сканирование», жми «Запустить».
  0:40  Таблица заполнилась. Показывай пальцем:
         - «Expired — сервис уже мёртв»
         - «Critical 9 дней — уведомление админу ушло автоматически»
         - «self-signed — этому сертификату никто не должен верить»
         - «mismatch — сертификат вообще не этого сайта»
  1:30  Кликни владельца → «Пётр, critical» → риск вырос.
         «Назначение ответственных в один клик».
  2:00  Фильтр «только проблемные», сортировка по Risk.
  2:20  Жми «Excel» — скачался отчёт. «Отчётность для руководства».
  2:40  Вставь expired.badssl.com и google.com → сканируй →
         «Работает на живом интернете».
  3:00  «Read-only: мы ничего не меняем в инфраструктуре.
         Модульная архитектура: дальше добавим AD-модуль, DNS-модуль
         и единый Infrastructure Risk Score» (по ТЗ §6).

ВОЗМОЖНЫЕ ВОПРОСЫ ЖЮРИ И ОТВЕТЫ:
  «Пароли не трогаете?»         — нет, только публичные сертификаты.
  «Domain Admin нужен?»         — нет, обычные сетевые права.
  «Как расставляется риск?»     — срок + цепочка + DNS + криптография +
                                   критичность сервиса, всё настраивается.
  «Что дальше?»                 — модули Identity/DNS/Service Radar
                                   по дорожной карте из ТЗ.


ЧАСТЬ 10. ЕСЛИ ЧТО-ТО СЛОМАЛОСЬ
───────────────────────────────────────────────────────────────────────────

  Статус Unknown у всех          — не запущен demo-стенд (Окно 1) или
                                   опечатка в адресе. Проверь Окно 1.
  «Порт занят» при запуске       — старая копия висит. В cmd:
      for %p in (8000 8443 8444 8445 8446 8447 8448) do ^
        for /f "tokens=5" %a in ('netstat -ano ^| findstr :%p ^| findstr LISTENING') do taskkill /F /PID %a
  Дашборд пустой после рестарта  — это нормально: нажми «Обновить» —
                                   данные подтянутся из базы (data/).
  Хочу начать с чистого листа    — останови Окно 2, удали файл
                                   data/cert_radar.db, запусти снова.
  «python не является командой»  — Python не установлен или не добавлен
                                   в PATH. Установи с python.org
                                   (галочка "Add to PATH"!).
  Медленно сканирует диапазоны   — уменьши размер CIDR (/24 → /28),
                                   увеличь Потоки до 128.

Полезные адреса, пока программа запущена:
  http://127.0.0.1:8000           — дашборд
  http://127.0.0.1:8000/docs      — интерактивная документация API
  http://127.0.0.1:8000/api/summary — данные KPI в JSON
